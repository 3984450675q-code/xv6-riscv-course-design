1. Another xv6 system call that could be accelerated with a shared read-only page is uptime. The kernel could maintain the current tick count in a page mapped read-only into each process, allowing user code to read it without entering the kernel. Updates would still be performed by the kernel, with suitable synchronization so that users observe a consistent value.

2. vmprint shows the three-level Sv39 page-table tree. Each indentation level represents one level of page-table traversal; each printed entry contains the index, raw PTE bits, and physical address. Page 0 contains the init program's code and data. Page 1 is the inaccessible guard page below the stack, so a user-mode process cannot read or write it because PTE_U is cleared. Page 2 contains the user stack. The third-to-last virtual page is USYSCALL, a user-readable, kernel-written page containing struct usyscall and the process PID. The final two pages are the trapframe and trampoline mappings.
